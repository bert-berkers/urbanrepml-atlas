## 3. Named list of every point where selection is made by the dumbest available layer

The Stage-1 prefilter inversion (row 7) is one instance. The others, each independently verified against source this session:

1. **Selflet Stage-1 substring prefilter** (`librarian_selflet.py:506-549`) — unweighted, unstemmed containment count over 6,830 rows; caps everything downstream (row 7). The central finding.
2. **`query_kind='all'` shared quota** (`:147-166`) — retention ("has this been done?", weak recency signal, ratified month-minimum depth) and protention ("is this still the goal?", strong recency signal) compete in ONE 50-row pool sorted by one `(-overlap, age_days-ascending)` key. The shared sort structurally favors protention's temporal logic and works directly against the ratified retentive-depth rule in `multi-agent-protocol.md`.
3. **Selflet cache key = `slugify(intent[:80])`** (`plan_kapstok.py:53,:481`) — S4 exact-match on a truncated slug of a *mutable* string. The one event most likely to invalidate the cache (the human revising the intent) is also the one event the key cannot survive.
4. **`_file_to_carry_item` durable-affordance surface** (`:1033`) — a rule/hook's entire searchable content is its first non-comment line ≤120 chars plus its path. The file's actual argument (the thing a rule exists to say) is structurally invisible to the selector that is supposed to decide whether it's relevant.
5. **`/niche` aged-item scan window** (`user-prompt-submit.py:191`) — `sorted(coord_dir.glob(...), reverse=True)[:5]`, a hardcoded 5-file window. An aged `[open|Nd]` item that fell out of the last 5 coordinator scratchpad files is invisible to this injection regardless of its age or severity, with no signal that anything was truncated.
6. **`build_niche_payload`'s plan-resolution fallback** (`:119-161`) — when `active_plan` isn't set on the terminal, it token-overlap-matches the intent against **today's** plan filenames only (`plans_dir.glob(f"{today_str}-*.md")`). A still-active plan from yesterday is structurally invisible to this fallback. This is the same substring-overlap shape as finding #1, implemented a second, independent time.
7. **9 "unconditional" rules' load-bearing status** is decided by the mere *absence* of `paths:` frontmatter — an S0 null selector where the criterion is "nobody scoped this," not a deliberate judgment that the rule's value justifies a ~22.6k-token floor tax on every single session regardless of task.
8. **`CLAUDE.md` / `MEMORY.md` whole-file injection** — the most extreme S0 case: there is no selection *within* the file at all; the entire document injects regardless of session relevance, at a combined ~9k tokens before any project code is touched.
9. **`SubagentStart`'s scratchpad tail = last 100 lines, constant** (`subagent-context.py:14`) — paid on **every** subagent spawn (not once/session), and the constant is compensated for by a *rule* (`multi-agent-protocol.md` §"Scratchpad Discipline" instructing agents to front-load summaries at the file's end) rather than by fixing the selector itself. A rule patching a selector's blind spot is a visible symptom that the selector, not the authors, is the dumb layer.
10. **`rebuild_retentive_index.py` / `rebuild_protentive_index.py`'s extraction regex** (`^## \d{2}:\d{2}...`) — the selector one layer upstream of everything else: whatever this regex fails to extract from the scratchpad tree never becomes a `CarryItem` candidate in the first place, and this session found no evidence anyone has audited its false-negative rate.

### 4.1 `/niche` aged-item injection silently dead on the happy path — FIXED

`build_niche_payload()` (`.claude/hooks/user-prompt-submit.py`) had `import re` nested inside the `active_plan`-fallback branch. Python scopes that import as a **function-local for the whole function**, so whenever the fallback branch was *skipped* — i.e. whenever `active_plan` WAS correctly set on the terminal, the normal, correctly-configured case — the later `re.compile()` call in the aged-item scan raised `UnboundLocalError`. The fail-open caller swallowed it silently. Net effect: the `[open|Nd]`/`[stale]`/`[escalated]` injection into every `/niche` UserPromptSubmit turn was dead **precisely when the terminal was configured correctly** — an injection surface that fails invisibly and specifically on the happy path, the worst possible failure signature for something meant to prevent items from being silently forgotten.

**Classification**: this is not a selector-*type* defect (S1, correctly scoped) — it's an **implementation bug in the delivery of an S1 selector's output**, arguably the closest thing to an S0 "silent, unrepresented overflow" in spirit even though the mechanism is a Python scoping bug rather than a corpus-size bound. Reproduced, fixed, and re-verified this session: commit `46360aff`. Nothing in the harness detected this on its own — it was found only because this audit's Thread F devops dispatch went looking.

### 4.2 The `Explore` agent cannot satisfy the mandatory-scratchpad contract

`multi-agent-protocol.md` requires every working agent to write a dated scratchpad entry (`<!-- SUMMARY -->`, prior-entries index, unresolved-items tags). The agent-tool registry grants `Explore` **no Write tool** (confirmed directly from this session's own tool-availability listing: `Explore` — "Tools: All tools except Agent, Artifact, ExitPlanMode, Edit, Write, NotebookEdit"). A dispatch to `Explore` this session correctly refused rather than silently fabricating a write, and its findings were lost to this session's record.

**Classification**: not a selection defect in the S0-S4 sense — it's a **contract that some agents are structurally unable to meet**, adjacent to the selection audit because it means `Explore`'s output is invisible to every retentive gatherer downstream (row 7/11): work `Explore` does leaves no trace for future selection to find, ever, by construction. Worth flagging alongside the selection findings because the failure mode rhymes: "the consumer cannot see what was discarded" (the diagnostic question from the theory note's §6.3) applies here too, just one step earlier — nothing was discarded by a selector; it was never eligible to be selected in the first place.

## 5. A′ — the recursive check

This session is itself a maximally-injected context (~35,391-token unconditional floor before any project code was read, per the census). Assessed honestly against the hypothesis the human offered to **falsify**, not confirm:

**Where injection demonstrably helped**: the JIT path-matched rules (row 4) fired correctly and usefully — `concurrent-edit-hazard`, `coordinator-coordination`, `multi-agent-protocol`, `no-fallbacks`, `training-discipline`, `helper-output-discipline` all landed because this session's tool calls touched `.claude/**` paths, and their content (commit discipline, scratchpad format, no-fallback posture) was in fact followed in this session's own conduct (pathspec'd commit below, scratchpad entry below, no silent dual-paths introduced). This is a real, working S1 selector doing its job — the one clean counter-example to the audit's own thesis, and it should not be stacked away.

**Where injection did NOT help, and had to be replaced by manual work** — *provenance class: this paragraph is the session's own **self-report** of its working process, corroborated by the surface-by-surface mapping in §2 above; it is **not** a ledger measurement. The `.claude/ledger` telemetry only went live at 14:23, mid-session, and its delta computation was validated on synthetic `Read` events, so it cannot retroactively instrument this audit's own reading. Read the claim at that weight — it is the weakest-evidenced item in this document, and it is also the only one so classed*: the three most load-bearing sources for THIS SPECIFIC audit — `specs/librarian_selflet_read_set.md`, `.claude/hooks/librarian_selflet.py`, and the 2026-07-27/2026-08-06 prior-art plans — were **never injected**. All three were found and read only because this session hand-Grepped and hand-Globbed for them, exactly the S3 (deferred-to-use, consumer's-own-effort) pattern the theory note describes as what the selflet ranking agent falls back to when its pool is insufficient (§4.4 of the theory note, measured independently there too). The unconditional 35k-token floor bought orientation and process discipline; it did not buy the one thing this task actually needed, which was "here is the file that answers your question" — that had to be pulled, not pushed.

**Honest n=1 verdict**: injection is doing real, verified work for *procedural* compliance (how to commit, how to scratchpad, what not to fall back to) and doing approximately **zero** work for *substantive* retrieval (which file has the fact I need right now) — the latter was entirely S3, hand-driven. This matches, rather than merely echoes, the theory note's independently-measured finding that the selflet ranking agent's own Grep/Read outperformed its pushed pool. It is not proof the hypothesis is right everywhere (JIT rules are a real counter-example, S4 skill/agent lookup is a real counter-example with low drift risk) — but for the specific problem of "find the right prior document," push-based injection contributed nothing this session that pull-based search didn't have to redo anyway.
